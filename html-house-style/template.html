Decision brief · Platform engineering

Move every team to one shared build cache this quarter

A shared cache should cut median continuous integration (CI) time by about a third, based on September's cold-start rate. It costs one platform engineer for six weeks, and we can reverse it in a day.

Draft 3Updated 22 Oct 20267 min read
Bottom line

Approve phase 1: put the four largest repositories on the shared cache by 30 November, then decide on the rest from measured results.

  • Why now: queue time grew 2.1 times between July and October (runner metrics), and CI is now the slowest step to production.
  • Cost: one engineer for six weeks, plus about $1,400 a month for storage and compute (cloud price sheet, Oct 2026).
  • Stop if: the cache hit rate stays under 60% after two weeks, or any build turns red because of a stale artifact.

One cache service sits between runners and storage

Runners ask the content-addressed cache before they build. A hit returns the stored output. A miss builds as today and writes the result back.

A shared service beats bigger runners on hit rate and cost

A. Shared service Recommended

One cache for all runners. Highest hit rate. Needs an owner.

B. Bigger runners

Keep per-team caches on larger disks. Fewer cold starts, same duplication, higher spend.

C. Do nothing

No cost now. Queue time keeps growing with headcount.

Phase 1 runs six weeks, in three steps

  1. Stand up the service (weeks 1 and 2)Deploy behind the existing load balancer. Read-only for one repository.
  2. Turn on writes for four repositories (weeks 3 and 4)Watch hit rate and stale-artifact errors daily.
  3. Decide (week 6)Expand, adjust, or roll back, using the stop conditions above.
Main riskA stale artifact could ship a wrong binary. Cache keys include the full toolchain hash, and phase 1 keeps a one-flag rollback.

Detail

How cache keys are computed

Key = hash of source inputs, lockfiles, toolchain version and build flags. Any change produces a new key, so nothing is ever overwritten in place.

Glossary

Cache hit rate
The share of build steps served from the cache instead of run again.
Cold runner
A runner that starts with an empty local cache, so it rebuilds everything.
Content-addressed cache
A copy of build output stored under a hash of its inputs, so an identical build can reuse it instead of running again.
